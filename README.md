# Neuro Draft

Веб-приложение на Django: по пику героев Dota 2 оценивает вероятность победы Radiant
и рекомендует героев на разных стадиях драфта

## Как работает

- **Модель** (`models/dota_model.pkl` + `vectorizer.pkl`) по полному пику 5v5 выдаёт
  `P(Radiant win)`
- **Рекомендатель** ([web/services/recommender.py](web/services/recommender.py)) выбирает
  метод по числу уже известных героев `n`:

  |  n  |  метод  |
  |-----|---------|
  |  0  | винрейт |
  |  1  | синергия с союзником |
  | 1–7 | винрейт + синергия + матчап - контр-риск |
  |  8  | дополнение до 9 путём выбора лучшего ответа противника |
  |  9  | перебор кандидата через модель |
  |  10 | прямой прогон модели |

## Запуск

```bash
python manage.py runserver
```

## Проверка качества

```bash
python quality_check.py NewMLDotaDB.csv
```
У текущей системы есть несколько проблем :

1)Она проверяет, насколько модель угадывает исход фактического матча, а не насколько герой, которого система рекомендовала, Реально подходи под ситуацию
Однако с другой стороны,после опроса знатоков(6 человек,у каждого из которых от 2500 - 15000 часов),выяснилось,что модель умеет реагировать на очевидные закономерности(Предлагает аппарата против 5 силовиков и предлагает Шейкера против Бруды Пла Цк и Наги)

2)Модель и статистики, считались и обучались на 75% от данных ,в то время как качество считается по всем данным,так что цифры можно назвать слегка оптимистичными

3.1)Стадии 1/10, 4/10 и т.д. зависят от порядка героев в базе данных, список героев не отражает реальный порядок драфта
Эта проблема была замечена слишком поздно, она решается путём Полного пересбора данных

3.2)Роли учитываются фильтрацией кандидатов, но не моделью, в её обучении,как и в базе данных,отсутствует информация о ролях
Также как и предыдущая проблема, данный изъян был замечен слишком поздно и тоже решается Полным пересбором данных



## ML-часть

Модель, датасет и подбор признаков - моя часть проекта. Конечная точность модели на собранном датасете 59% угаданных результатов матчей.

**Данные.** Датасет из около 1 млн (1 003 574) рейтинговых матчей Dota 2 в режиме All Pick, собранных через OpenDota API. Для каждого матча хранятся составы Radiant и Dire (по 5 героев), средний ранг матча (`avg_rank_tier`) и исход (`radiant_win`). Файл с данными: `NewMLDotaDB.csv`. Скрипты сбора лежат в `ml/`.

**Подбор модели и признаков.** Я долго искал, как правильнее представить драфт на входе модели и какая модель лучше с ним работает. Перебирал градиентный бустинг (в том числе XGBoost) и другие бустинговые модели, GLM, регрессию, пробовал представлять героев эмбеддингами. В итоге остановился на варианте, описанном ниже.

**Итоговая модель.** `XGBClassifier` (`binary:logistic`) выдаёт вероятность победы Radiant по полному пику 5v5. Признаки разреженные, собираются через `DictVectorizer`:

- средний ранг матча и ранговая группа
- каждый герой на своей стороне (Radiant / Dire)
- пары героев внутри одной команды (синергии)
- пары героев из разных команд (матчапы)

**Оценка качества.** Считается скриптом `quality_check.py`. Ограничения такой оценки честно описаны выше, в разделе «Проверка качества».

**Скрипты в `ml/`:**

- `dotaapi.py` - сбор матчей и пиков через OpenDota API (первая версия датасета)
- `new.py` - дополнительный сбор рейтинговых матчей All Pick в `NewMLDotaDB.csv`
- `test.py` - ранний эксперимент с XGBoost на хешированных признаках
